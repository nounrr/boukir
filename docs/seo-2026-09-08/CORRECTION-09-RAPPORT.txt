nom AR proposé, parent actuel, parent proposé, slug, classement, validation du nom,

Répartition proposée :

3. APPLICATION RÉVERSIBLE

Le script backend/scripts/apply-category-nomenclature.mjs fonctionne en simulation
par défaut. Avec --apply, il :

- verrouille et relit les lignes dans une transaction ;
- refuse l’application si les données actuelles ne correspondent plus à l’inventaire ;
- crée une sauvegarde JSON avant toute modification ;
- applique uniquement les noms marqués approved ;
- ignore l’ID 74, qui exige une validation métier ;
- reste idempotent lors des exécutions suivantes ;
- sait restaurer une sauvegarde avec --rollback sans écraser une modification plus
  récente faite après l’application.

La simulation contre la base locale a été refusée sans modification : cette base est
ancienne et diffère de l’inventaire de production sur 72 lignes. Ce refus est voulu et
prouve que la protection contre la dérive fonctionne. Le script n’a pas modifié la
base de production.

Procédure sur le serveur de production après déploiement :

1. cd /var/www/boukirEcom
2. npm run categories:audit -- https://boukirdiamond.com
3. npm run test:categories
4. npm run categories:mapping:plan
5. Lire le plan et vérifier que la source est bien la base de production.
6. npm run categories:mapping:apply
7. Redémarrer le backend qui sert /api/categories si nécessaire.
8. Refaire l’audit et les contrôles FR/AR listés à la section 6.

Exemple de restauration, uniquement avec le chemin affiché par l’application :

node backend/scripts/apply-category-nomenclature.mjs --rollback backend/category-nomenclature-backups/categories-AAAA-MM-JJTHH-MM-SS.json

4. MAINTIEN DANS LE BACKOFFICE

La création et la modification d’une catégorie exigent maintenant un nom arabe dans
l’API. Les deux formulaires du backoffice affichent ce champ comme obligatoire. La
liste montre le nom arabe à côté du français, signale une valeur manquante et la
recherche accepte les deux langues. Cela évite de recréer progressivement le défaut.

5. CAS MÉTIER À ARBITRER

Aucun parent n’est modifié automatiquement. Les décisions restantes sont regroupées
ci-dessous ; il ne faut pas fusionner les catégories avant d’avoir contrôlé tous leurs
produits.

2. IDs 73/74 — Matières et matériaux de construction : l’ID 74 mélange isolants,

   définir les frontières et reclasser les échantillons incohérents.

   doit devenir parent ou rester une famille indépendante.

   selon l’usage métier.
